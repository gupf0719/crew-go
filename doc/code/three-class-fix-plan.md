## A 类 · 「接受」与「兑现」是两个动作

### ⚠️ 更正：不是 3 个实例，是 ≥7 个；而我漏掉的那半更严重

我把问题框成「未知键静默丢」。真正的洞是**已知键解析了却零消费**：

| 字段 | 实况（已复证） |
|---|---|
| `SkillDescriptor.AllowedTools` | 写入 + 清洗，**零消费**。业务写 `allowed_tools: [read_file]` 期待限制工具，**零强制** |
| `MultiTurn` / `MaxTurns` | ~~各 1 处引用，只有写入~~ **已删（2026-08-27）**——spec 语义预设「skill 激活后跨轮活着」这个我们没有的状态 |
| `InputSchema` / `OutputSchema` | ~~struct 有字段、parser 无 case~~ **已删（2026-08-27）** |

**任何「未知键严格模式」都抓不到它们**——它们是**已知键**。只按原框架修，这个**安全形状**的静默失效原样留着。

另有一条拼写不匹配：连字符约定只落实 **2/6** 个多词键（`disable-model-invocation`/`user-invocable` 收了，`when-to-use`/`multi-turn`/`max-turns`/**`allowed-tools`** 都收不到），而外部生态用的正是连字符 ⟹ 拷一份过来**4 个字段静默消失**。

### 根因

`skill/discover.go` 是**手写 YAML parser**，struct 上打的是 `json:` tag 不是 `yaml:` tag ⟹ **struct 不是 parser 的真相源**。三份产物之间零机械约束：

```
SkillDescriptor 结构体  = 意图的 schema
parseFrontmatter switch = 子集的实现
各消费点                = 更小子集的实现
```

已经漂了 3 次。这正是 CLAUDE.md「**『必须与 X 保持一致』是设计债的自白**」——只是这里连那句注释都没有。

### 修法（按依赖顺序）

**1. 校验点前移：从「用到时」到「加载时」**（成本最低、收益最大）

现状唯一存在的校验（未知 `context` 值）在**激活期**、结果是 `tool.Failure` ⟹ **收件人是 LLM，不是业务开发者**。

而 `ParseSkillMD` 的签名里**已经有 `error` 且恒 nil**，调用点（`skill/skillbox.go`）**已经在 handle**。**报告链路是通的，从没往里送过东西。** 不需要动任何公开 API。

**2. 未知键的处置判据：「这个键是不是行为开关？」**

调研给的不是「都选严格」，是一条按 schema 所有权分叉的判据，而 k8s 把这个问题的两半分开了：未知**字段** → 默认 `Warn`；未知**feature gate 名** → **硬报错**。

- **是行为开关**（不存在 ⟹ 你要的行为百分之百没发生）⟹ **报错**。`paths` / `context` 在此列，且都是安全或成本相关。

  > **⚠️ `allowed-tools` 已从这一档移出（2026-08-27 落地，commit `cbff078`）。** 上面那条
  > 判据默认了「行为是良定义的，只是没实现」——`allowed-tools` 不满足这个前提：`fork`
  > 默认路径下子 agent **一个业务工具都不给**（安全期望已被超额满足，没有可裁的东西）、
  > 配了 `WithSkillSubAgentResolver` 时那是业务自己的 agent（框架伸手改它的工具集越界）、
  > `inline` 下 body 注入一次就完了（**没有作用域边界可挂**）。三种路径没有一种能让它有
  > 良定义的语义 ⟹ **没有可报的错**。落地是解析期 `slog.Warn` + godoc 指向
  > `agent_v2.WithToolFilter`（那个有明确作用域：每轮 model 调用前问一次）。判据见
  > `skill/skill.go` 的 `AllowedTools` godoc。
- **描述性**（可能来自更新的 spec）⟹ **留而不丢**（收进 `Extra map[string]string`）。

  > **⚠️ 2026-08-27 补挖后，这条判据本身被证据部分推翻。** 实挖到的分叉不是「行为开关 vs
  > 描述性」，而是 **「schema 归谁所有」**：同一个仓里，第一方配置与 tool call 参数（schema
  > 我们定）**严格拒未知键**，第三方 skill 文件（schema 在生态里演进）**静默忽略**。
  >
  > 而它敢忽略的前提是**schema 极小**——那边的 skill frontmatter 只解析 3 个字段
  > （name / description / metadata.short-description），我们是 15 个。**你不解析的字段，
  > 不可能变成「解析了但没兑现」，也不需要为它设计未知键政策。**
  >
  > 所以这一类的正解顺序是：**先把 schema 收到只剩真的兑现的字段**，再谈未知键怎么办——
  > 而不是反过来给 15 个字段设计一套分档报错规则。对照见
  > [skill-system.md](../description/three-way-comparison/skill-system.md) 末节。

⚠️ 「宽松」有两种别混：pydantic 三档 `ignore`(丢) / `allow`(留) / `forbid`(报错)，**静默丢是三档里最差的**——它连「事后能查」都不给。**光是从「丢」挪到「留」就拿到大部分收益且零兼容代价。**

**3. 机械对账**（唯一挡得住「已知键零消费」的手段）

`SkillDescriptor` 每个导出字段，除写入点和清洗点外必须至少还有一个引用。这是 CLAUDE.md
「producer ↔ consumer 数量对账」的直接应用。

> **⚠️ 这条提案原样落地会永久红，别照抄（2026-08-27 复跑后补）。** 复跑结果是
> `MultiTurn` / `MaxTurns` / `UserInvocable` 三个红——而 **`UserInvocable` 是有意零消费**：
> 它管的是 user-facing 列表，框架不拥有那个面（无 slash command / CLI），godoc 早写明
> 「框架不做强制」。**一道永久红的闸等于没有闸**——人学会忽略它，下一个真的漏了的字段
> 也跟着被忽略。所以这条要么带一张「有意不强制」的豁免名单（且名单里每一项必须在 godoc
> 里给出理由），要么干脆别做。
>
> **✅ 已落地（2026-08-27），但形态换了**：闸没有去数消费点（`.Name` 这种名字满仓都是，
> 机械 grep 不可靠），改成**每个导出字段必须在自己的 godoc 里声明处置**
> （`[框架消费]` / `[业务自负]`），`TestSkillDescriptor_EveryFieldDeclaresDisposition`
> 用 `go/ast` 对账。零 consumer 的四个字段一并删掉，所以闸开局是干净的、不会「永久红」。
> 标记**逐字段各带各的**——共享一条组注释会让新字段静默继承，闸照样废（有 sanity-revert 钉）。
>
> 另：原文那句「今天跑一遍红 3 个」现在**仍然是 3 个，但集合换了人**（`AllowedTools`
> 补了 warn 出列、`UserInvocable` 进来）。**光看计数会以为什么都没发生**——这正是本仓
> 「budget 型哨兵不收紧」那个形态：只锁总数的闸，修好一个就腾出一个名额给下一个，
> 静默通过。要锁就锁**按字段名的名单**，不锁数量。

**4. 消灭拷贝**：换 `yaml.v3` + `yaml:` tag。`InputSchema`/`OutputSchema` 那类结构上消失，连字符变成 tag 里写一次的事。

## B 类 · 防线只有终点，没有中途

### ⚠️ 更正：那堵墙根本不是墙

我写的「撞 `maxRounds` ⟹ 整个 Run 的工作全废」**在框架层不成立**：

- maxVisit 的计数器是 **Run 局部变量**（`visits := make(map[NodeID]int)`），从不入 cp
- 触顶时 frontier 非空 ⟹ 存档（`Status=Failed`）
- 2026-08-13 起三处闸门按 `HasResumableWork()` 判 ⟹ **失败档续得上**
- Resume 会拿到**全新的轮次预算**从断点继续

**工作没废。但这让问题更糟，不是更轻**：

1. 调用方拿到的是 **error 不是答案**——模型从没得到「把手上的东西收个尾」的机会。
2. **这堵墙拦不住任何东西**。预算免费重置 ⟹ 天真的自动 Resume 就是一个无进展的无限循环，而每一轮都报成失败。**既没有墙的保护，又有墙的代价。**
3. **没人学到任何东西**。「任务大所以超轮」和「同一个工具调了 20 次」在指标上完全同形。

⟹ 代价不对称**成立，但理由要换**：不是「工作全废」，是**这个信号既不能自救也不能自止**。

### ⚠️ 更正：干预是三种形态，不是「注入 vs 中止」二选一

我漏掉了最便宜的那一档。

| 形态 | 做什么 | 谁在用 |
|---|---|---|
| **A 注入** | 往对话里加一条提醒，让模型自救 | 4 家，分级阈值 |
| **B 软降落** | **预算耗尽时把工具摘掉（`tool_choice="none"`）再调一次模型** | MAF / CrewAI |
| **C 硬墙** | 抛异常 | 我们 + 3 家 |

**形态 B 是我完全没想到的，而它比 A 更便宜**：不需要检测器、不需要新配置、不需要新状态、不需要新的注入通道。而它恰好直接对上上面那条更正——**把「报 error 且预算免费重置」变成「产出一个答案 + 一条指标」**。

**没有一家从提醒升级到拦截**。有一家把这条明确否决并写进决策记录，理由是：被拦的调用会**惩罚合法的重复**（轮询长任务、重查一个预期会变的文件），而提醒**把控制权留给模型**。

### 逐条修法

| 实例 | 判断 | 依据 |
|---|---|---|
| **软降落（形态 B）** | **先做这个** | 最便宜、直接对上前提更正、不需要在四个实例间取舍 |
| **重复调用检测** | 做，但**三条语义比算法重要** | 8 家只有 2 家有（这是负面事实）。三条语义：**未跟踪工具对链条透明**（否则记账工具洗白循环）/ **被拒的调用照样计数**（正是我们的 deny 子案例）/ ~~**per-agent 键控**~~ → **按「调用流」键控**（见下方更正） |
> **⚠️ 更正（2026-09-21，`1f03f73b` / `94323cdb` 落地后实测）：上表「per-agent 键控」不够，
> 正确的维度是「一条调用流」= graphNS + agent 名。**
>
> 「按活对象键控」这个直觉落到代码上会写成 `key = cfg.Name`，而 `RunSession.values` 在并发
> 分支之间是**共享的**（`ForkLane` / `NewSharedChildSession` 都共享 map 与 mu）⟹ 两个**同名**
> 的并行分支撞进同一条链。实测两层后果、都不报错：计数**跨分支合并**（各调 2 次凑成 4 次触发
> 阈值 3）+ `count++` 与 `fired` 的 map 写**裸奔在锁外**（`valuesMu` 保的是 map 槽，不是指针

> 同一个错误形状在**工具级渐进披露的揭示集**上也存在（同样只按 agent 名键控），后果更重：
> 一个分支检索解锁的工具，另一个分支白拿，fail-closed 被击穿。两处已一并修成 ns + agent 名。
>
> 根因是 CLAUDE.md 记的「**借来的量里没有新用途的意思**」——`cfg.Name` 里没有「哪条调用流」。
> N=1（单 agent 顶层跑）时碰巧够用，N≥2 才错。同包的 `routePendingKey(ns, idx)` 早就是对的形状。

| **per-call 超时** | 做成**可选接口、无全局默认** | **没有一家给非零全局默认**。理由：**超时是协作式的，给不协作的东西设超时是撒谎**。**在 Go 里尤其致命**——`context.WithTimeout` 只关 `Done()` channel，工具不 select 等于没设；而「抢跑」写法**泄漏 goroutine**，正是 CLAUDE.md 明令禁止的。形状对齐已有的 `tool.Categorizer` |

| **后台 job 协议** | **不做（defer）** | **零个库层先例**。3 家有的**全是产品**，0 家 SDK 有。跟我们 TodoProvider 那条决策用的是**同一个产品/SDK 判据**，而那条已 defer——这批数据是它更强的支撑，**别重开这个话题** |

### ⚠️ 软降落的形状：`(答案, err)` 而不是 `(答案, nil)`

**2026-08-26 追加一轮调研后改写。** 原方案打算照抄「产出答案不抛异常」，那是错的——两家
先例的返回值里**没有任何字段**标记「这是被逼出来的」（一家的信号是 `verbose` 才打的终端
黄字、另一家是 `logger.info`），调用方拿到的是 **`err == nil` 的半成品答案**。

**而 `maxRounds` 既可能是保险丝也可能是预算，取决于产品怎么用**——那么框架就**不该替产品
决定**。Go 标准库给了唯一不用决定的那个形状（`strconv.ParseInt` 的 `(clamped value,
ErrRange)`：结果照给、error 照返）：

- 当**保险丝**用的调用方：`if err != nil` ⟹ 跟今天完全一样，触顶就是异常
- 当**预算**用的调用方：`errors.As(&e)` 后读 `FinalMessage(events)` ⟹ 拿到那条答案

一个形状同时服务两种用法，**不需要开关、不需要新枚举、不需要新 API**。而且
`agent_v2/basic_agent.go:258` 证明「错误路径上照常返 events」**已经是本仓既有风格**。

⚠️ 顺带纠正本文另一处：原文按「产品 vs 库」区分谁需要结构化信号——**那个分野是错的，
证据是反的**（信号最丰富的两家是产品，只用日志的三家全是库）。真正的判别式是**「输出要不
要跨进程序列化」**，而它对我们是**加强**：我们有两个 wire 消费者 + 编排嵌套（子 agent 的
结果由父编排的**代码**消费）。

⚠️ 还有一条结构性可疑点值得记：**做软降落的四家一个标记都没有；做标记的四家没一家在模型层
软降落——两个集合完全不相交。** 推断是它们服务不同的人（软降落服务读文字的人，标记服务
消费结果的程序）。把两者当套餐可能是把两个需求混成一个方案。

### ⚠️ 一个不免费的地方

注入通道**已经存在**（`OnModelStart` 改 `modelIn.Messages` 确实被消费），但那次改写是**瞬态的**——`msgs` 是局部变量不写回 channel ⟹ **提醒不进 cp、不进会话历史**。

而提醒是「当时发生了什么」的一部分，瞬态注入会让存档里的历史**解释不了模型下一轮为什么改了主意**。有一家把「model-visible ⟺ logged」当成不变量，专门为此选了合成 user message 这条路，并**明确拒绝**顶替 tool_result（「那会让存档里的 tool_result 对工具实际返回的东西撒谎」）。

## C 类 · 多件事同时发生，报告只能报一件

### ⚠️ 更正：我把实例 3 归错类了，而它是三条里唯一造成功能损失的

实例 1、2 是**仲裁**（N 件事，返回值一个位置）。
**实例 3 是归属判定**——`errors.Is(err, context.Canceled)` 回答的从来不是「**我的** ctx 死了吗」，而是「这条错误链上有没有出现过某个 ctx 错」。**单分支、无并发时一样错。**

**实测（已复证，逐字吻合）**：

```
caller ctx.Err()                    = <nil>      ← caller 的 ctx 是活的
errors.Is(apiErr, DeadlineExceeded) = true
IsControlFlowSignal(apiErr)         = true
IsRetryable(apiErr)                 = false      ← 不重试
DefaultFailoverPolicy.ShouldFailover= false      ← 不切候选
[对照] 普通网络错: CFS=false Retryable=true Failover=true
```

⟹ 给模型客户端配 `http.Client{Timeout}`（**标准做法**）⟹ **`fallback` 在它最该发挥作用的那个场景（provider 变慢/超时）永远不切换**。

**最阴的一档**：`net.Dialer` 超时的错误串是 `i/o timeout`，字面上跟 context 无关，但 `errors.Is(err, context.DeadlineExceeded)` **是 true**（stdlib 主动这么设计的）——所以连「grep 错误串里有没有 context」都救不了。

**根因**：一个谓词被两个问题共用，而两个答案相反——正是 CLAUDE.md 那条判别式的实例（**「一个选项/字段，有没有两个调用方对它的期望是相反的？」**）：

- **A 类调用点**「这个错能不能被吞成 tool.Failure？」——过度包含**无害甚至更对**
- **B 类调用点**「要不要再做一次？」（`IsRetryable` / `ShouldFailover`）——过度包含**有害**

**修法**：`IsControlFlowSignal` 的前三档（自有哨兵 `InterruptError` / `ErrSoftCanceled` / `ErrCheckpointStale`）**保持 errors-based 不动**——第三方后端伪造不出来。**只有最后那一行**（两个 ctx `errors.Is`）换成 `ctx.Err() != nil`，因为 `context.Canceled/DeadlineExceeded` 是**全生态每个网络库都在产**的东西。

⚠️ 必须一起想的边界：**软取消不动 ctx**，基于 `ctx.Err()` 的判断看不到它 ⟹ 不能把整个谓词换成「只看 ctx」，三个自有哨兵那半必须留着。

> ⚠️ **2026-09-18 核验：落地形态跟上面的修法不一样，而且只接了一半**。实际做法（`44b6ccb4`）是**新增** `IsRetryFutile(ctx, err)`，
> `IsControlFlowSignal` 本身没改；接上新谓词的只有框架重试守卫与 fallback（`fallback/policy.go`）。B 类调用点里的
> **`IsRetryable` 仍先调 `IsControlFlowSignal`**，而它是 `SimpleRetry` / `ExponentialBackoff` / 7 个 `WithXxxMaxRetries` 的默认谓词
> ⟹ 上面那段实测里的 `IsRetryable(apiErr) = false` 今天依然成立。见 `todo.md` 里 `IsControlFlowSignal` 误判那一行。

代价：`FailoverPolicy` 接口要加 ctx 参数（破坏性，但项目未上线）。**同一个 feature 的正解现成**——有一家的故障切换就是 `if ctx.Err() != nil { return false }`，而且它的 policy 签名**把 ctx 传给了业务**；我们的 `ShouldFailover(err error) bool` **业务自己也没有 ctx，想修都修不了**。

**7 处独立先例**（`net/http` / `database/sql` / `grpc-go` ×4 / `errgroup`）全部是**问 ctx 不问 error**。唯一反例是「把 handler 错映射成上报的 status code」——那是**贴标签**，标错顶多不精确。

由此得到的判别式：
> **`errors.Is(err, context.X)` 可以用来「贴标签 / 报状态 / 打 span」，不能用来「决定要不要再做一次」。**

### 实例 1、2：Q1 的答案是「根因修法已经在代码里了」

四家框架**独立收敛到同一个切分**——而且其中三家在报告层都有我们已经修掉的那类 bug，它们之所以不炸，恰恰因为**后果不骑在返回值上**（中断已经写进 checkpoint 了，raise 掉不影响 resume）。

> **仲裁只决定「谁被看见」，绝不决定「发生什么」。**

我们的 `AbortErr` / `StayPending` **已经是这条规约的实例**，godoc 里那句「它是**事实**，而 `exitErr()` 是**报告**」就是它的完整表述。**缺的不是新机制，是把它提成一条判别式**：

> 往 `exitErr()` 的仲裁阶梯里加一档之前先问：**有没有任何代码路径因为这个错「赢了」而做出不同的动作？** 有 ⟹ 那个动作必须搬到独立字段上，仲裁只留展示。

**「主错 + Others []error」这个提案：五家都没人这么干。** Go 侧的聚合库全是 any 语义（`errors.Join` / `multierr` / k8s `Aggregate`）。k8s 的注释直接承认了我们实测出的那个危险，处理办法是**干脆不支持 `As`**。

规律：**聚合只在同质类别内做，且落进领域类型的复数字段，绝不落进 error 的 unwrap 图。** 我们现在多中断路径的 `errors.Join`（全是中断分支）**符合这条**。

### 实例 1（顺序）：修，但理由不是「让它稳定」

**顺序信息本来就有，是被 `assembleFrontier` 的 map 扔掉的**（出边是按 `AddEdge` 声明序的 slice，只有那一处灌进 set）。修它**不是发明仲裁标准，是别丢已有的**，约 5 行。

论据用**分布形状**而不是「可复现」：实测 10000 次是 **87/13**，不是 50/50。
**5 次的 CI 大概率一次都撞不上，40 次撞 4~5 次，线上按流量撞**——「测得过、线上炸、复现不了」。

### 实例 2：比我描述的更严重

`a2a/server/executor.go` 从**返回值**算 `notResumable`。被兄弟中断吞掉时 ⟹ `keepPending=true` ⟹ **服务端把任务挂成 `input-required`、把问题发给远端、等一个注定再撞同一份坏存档的续发**。

⚠️ 而 `ErrCheckpointStale` 那条之所以没事，是因为它走**同一分支内双 `%w`**——**跨分支时那个机制不成立**。

修法：提进仲裁阶梯（判据统一成「**回答这个问题有没有可能有用**」），但**必须是独立字段**而不是复用 `AbortErr`——那份档要留着排查，不能触发 `purgeCpSubtree`。正好又是上面那条规约。
