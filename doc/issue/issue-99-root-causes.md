## 1. 根因（终版）

### 1.1 先分清两类语法相同、语义相反的东西

| | 形态 | 是不是问题 |
|---|---|---|
| **类型 1** | 调用方没填可选参数 ⟹ 用文档写好的默认 | **不是**。调用方表达的是「我没意见」，而默认值**就是「没意见」的定义**——问题被回答了 |
| **类型 2** | **我查了，没查到，但我必须往下走** | **是**。这是我们那五处 |

两类都长成 `x ?? default`。对端抽样 26 处 `??`，**22 处是类型 1**。按类型 2 的口径数，七家**基本不挑默认**。

### 1.2 根因

> **一次访问的「谁」没进寻址、访问者又不唯一 ⟹ 只能补一个判断；判断的输入访问者拿不到
> ⟹ 它答不上。**
> **答不上时选了「挑一个默认」而不是「拒绝回答」，才变成静默失效。**

证伪轮专门找反例没找到、五家全部封口的**核**（它把链里隐含的前提「写操作不可交换」挑明了——
可交换的位置走 §3 出路①，链根本不启动）：

> **一个承载「框架控制决策」、且「写操作不可交换」的共享槽，若写入者多于一个，
> 就必须有一个跨全部写入者成立的确定性裁决依据。**

我们五处补判断的共同点**不是「答不上」，是每一处都在答不上时挑了默认**：

| 补判断 | 它答不上的问题 | 答不上时它选了 | 位置 |
|---|---|---|---|
| 「哪些工具不进 memo」的名单（`isFrameworkTool` 兼职分类器） | 这个工具的产出是不是只有 tool_result？ | **默认放行**（进 memo——业务自定义控制流工具的槽外副作用会被重放静默跳过） | `agent_v2/basic_agent.go:2160`（名单判定；契约注释 :2117 起） |
| 两处「摘掉 ctx 收件槽」 | 我这一层是不是「那次调用」？ | **默认继承**（ctx 天然下传，没摘的层都收得到） | 摘槽点 `agent_v2/agent_tool.go:239`、`agent_v2/skill_tool.go:672`；摘法 `agent_v2/handoff_tool.go:129` |
| 「我是不是 sub-agent」布尔 | 我这次算不算写入者？ | **默认 false**（当自己是顶层，抢写父 ns） | 读点 `agent_v2/basic_agent.go:1486`；push 收敛后仍是布尔 |
| 拿 wire 会话 ID 当唯一键 | 这个 ID 是不是我的？ | **默认认领**（谁带这个 ID 谁就是主人） | `agui/handler.go:132`（threadId → 挂起会话）、`agent_v2/handoff_agent.go:675`（threadID → 持久 active） |
| 按 tool_call 下标裁决——**仅跨批那半是类型 2**：批内 idx 是模型声明序（`:249` 取自 `GetCurrentToolCallIndex`）＝现成的出路②，无缺失信息 | 哪个分支的下标 0？ | **两层默认叠加**：put 同格后写覆盖（`:80`，证据在写入时就被销毁）＋ take 跨空间取最小 | `agent_v2/handoff_tool.go:80` / `:84` / `:249` |

⚠️ 五处**不是**都改 fail-fast——处置按 §8 待决 2 的三步走（先判类型 1/2，再判
「拒绝有没有良定义」，剩下的才选拒绝 / 降级留痕 / 交还模型或用户）。

2026-08-20 逐处代码复核另补三条：

- **memo 名单两个方向的错都静默**：放进 memo 错在「漏重建临时载体副作用」（工具体被跳过、
  err=nil），排除出 memo 错在「外部副作用双跑」（扣两次款）——判据一确认此处无两全答案，
  是真类型 2。
- **摘槽的判断不是答不上，是只有嵌入点答得上**：AgentAsTool 与 skill fork 两处被问过且答对
  （摘了），默认落在**从没被问过的新嵌入点**头上。且按判据三现方向选反了——摘错了会
  **可见**软失败（`HandoffNoCoordinatorErrCode` 回灌模型改自答），继承错了是静默劫持；
  不摘服务于「组合编排本身是候选」这个特性，张力指向 §6 的必填/显式传递方向。
- **链的末环在本仓有正反两个现成样本，就在同一个文件**：transfer 找不到槽时选了**拒绝**
  （软失败可见回灌），撞格时选了**默认**（静默、实测胜负 21:9 随调度）——「答不上时挑默认
  才静默」不是推测，是对照实验。

### 1.3 三条判据（决定「答不上时该怎么办」）

**判据一（主轴）：存在一个「不论缺失的信息是什么都正确」的答案吗？**
有 ⟹ 那不是默认，那**就是正确答案**，取它。没有 ⟹ 你是在几个互相竞争的答案里挑一个。
对端 10 处「合法静默默认」全是**空动作 / 保守上界 / 原样保留**，**没有一处是「猜一个具体值」**。

**判据二：爆炸半径决定处置，不是问题难度。**
原话：「a stale copied field may at most **mislabel telemetry, never grant control**」。
**允许被默认、被环境隐式携带的东西，其出错的最坏后果必须止步于「标错了一个标签」。**

**判据三：「忘了标注」时哪个方向的失败会显形。**
不是「哪个默认更安全」，是**「开发者忘了标注时，两种错各自长什么样」——选那个错会显形的方向**。
原话：默认设成必填 ⟹ 忘了就**过度拒绝（不方便）**；默认设成可忽略 ⟹ 同样的疏忽就
**静默续跑一个被掏空的会话（安全故障）**。

### 1.4 ⚠️ 一个位置性的例外：有些地方**禁止**你拒绝——复查后：我们没有一处站在那儿

对端同一个文件里同一个问题两个答案：普通 reducer 对「删除的 ID 不存在」**报错**，delta
reducer 同场景**静默忽略**。理由是后者必须满足 `reducer(reducer(s,xs),ys) == reducer(s,xs+ys)`
（分批喂与合批喂结果必须相同——它的存档只存哨兵，重建时按**存储层选的分法**重放写入）。
上一版从中概括出「如果『没找到』是到达顺序的函数而不是正确性的函数，拒绝就没有良定义」——
概括经代码追踪属实（重复删除跨批：合喂不报、分喂报），但**那句是我们的转述，不是对端原文**。

**禁止拒绝成立需要两个前提**：① 判定函数会被它不控制的外部层以**不同分法重复投喂**同一组
写入（live 小批 vs 重建大批）；② 拒绝判据**按批、对中间累积态**求值——真值随批边界漂移。

**复查（2026-08-20，本仓代码 + 对端源码双向验证）：两个前提我们一处都不满足。**

- **下标裁决不满足**：槽是 per-call / per-attempt 对象，不进 cp、无重放；`take()` 只在成员
  调用完整返回后执行一次（`agent_v2/handoff_agent.go:582`），拒绝判据「∃ 同 idx 异 target」
  是**完成后写入集合的纯函数**——调度只决定哪次 put 报错，不决定报不报错。
  **拒绝在此处良定义**，上一版「fail-fast 可能立不住」的疑虑撤销。
- **Append/Sum + 超步提交也不满足**：我们的 cp 存**物化 channel 值**
  （`compose_v2/checkpointer.go:162`），每条写入 fold 一次、从不按别的分法重喂——是
  「fold 一次存值」位，不是「存哨兵按分法重放」位。上一版「正是这个处境」的断言撤销。
  仅存的弱同款是「中断恢复把一个超步的提交拆成两次」，它只约束「结果依赖分批」的
  reducer——Append/Sum 天然不变，不受影响。
- 对端在**同构位置**（哪个并发投递是 0 号）的答案既不是拒绝也不是先到先得，而是
  **提交点铸全局确定性下标**（写入合并、排序之后统一编号）——即出路②，与 §7.3 的订正一致。

## 2. 「谁」是三个不同的东西，修法互不通用

证伪轮的核心修正：把三者压成一个「谁」，**正是前两版归纳看起来能覆盖全部症状的原因**；
不拆的话会给一批症状安错成因——已实锤安错过的两条见 §7.3（memo 名单、下标裁决）。

| 语义 | 我们的症状 | 对端解法 |
|---|---|---|
| **A 访问者身份**（哪段代码在碰容器） | memo 名单 / 摘槽 / `isSubAgent` / 下标裁决 | **接手方进场时按自己视角重铸视图**（2026-08-20 订正：原记「交出控制权前」方向反了——对端的重铸发生在接收方 Run 入口、以接收方身份为基准）· 提交点全序 · 可交换聚合 |
| **B 归属主体**（这份数据是谁的） | 跨租户 / agui 挂起会话被销毁 / wire 会话 ID | metadata + **认证过的**边界过滤器——**在边界层，不在引擎层** |
| **C 任务代号**（属于哪一次任务） | RunID 继承 / 成员记忆写不进去 | 换一个新身份 |

三拆分别对应「读 / 查 / 写」三问：读的时候「谁读」进不进寻址（A）、查的时候「谁的」
进不进 key（B）、写的时候「谁写」进不进 key（C）。同一个缺陷可以踩两拆——
`isSubAgent` 开关问的是 A 的问题，堵的却是「写入者身份没进 key」（C）的洞，
所以 §4 里问题 1 和 2 必须一起修。

## 3. 出路（五条 + 一条正交）

| # | 出路 | 前提 / 代价 |
|---|---|---|
| ① | **让聚合可交换 / 内容自带身份** | 写操作能定义成幺半群；**裁决依据不必长在寻址里** |
| ② | **提交点定确定性全序** | 多个写入者必须都保留、但顺序要确定 |
| ③ | 让访问者唯一 / 让访问不发生 | 第二个访问者本就不该存在 |
| ④ | **值上盖章**（生产者声明，消费者只做比较） | **见 §3.1——它不是天然可靠的** |
| ⑤ | 补判断 | 判据必须在访问者坐标系内；**答不上时拒绝回答** |

**正交一条**（单独管静默还是报错）：**守卫的作用域必须盖得住容器的作用域**。

**第三条出路（agent 框架独有，对端出现 4 次）**：**把问题交还给唯一能重问的那一方**
（模型 / 用户），并在错误正文里**把「你该给什么」直接给出来**——那恰好满足我们
「守卫合法当且仅当调用方能用手上已有的信息满足它」这条规约。

### 3.1 ④ 的成败条件

④ 之所以最贴我们：**五处答不上的共同原因是值上没有戳**——「这个工具的产出是不是只有
tool_result」若工具自带一个 trait 自述字段就不是问题。对端同款：地址段带类型标签、
工具带 `_is_codex_tool` 式自述、pending 请求记录里存返回地址、存档自带身份戳。

> **但这条出路的成败完全由「章怎么保证被盖上」决定。**
> 弱档实现（字段可选、盖章散在 N 个构造函数里）忘了盖章**静默走默认**——
> **退化成和补判断一模一样的失败形态，只是把判断从消费者搬到了生产者。**

对端实锤：某家 42 个事件类里**只有 8 个调了盖章函数**（2026-08-20 复核数字精确复现：
直接子类口径恰 42、恰 8 个调那**对**盖章函数——盖章实为成对两个）；某家的类型章
「没实现就反射兜底」；某家的作者名「缺了就继承上一个分片的」。

**做成可靠的手段，按「买到多少 / 花多少」排**：

1. **让调用方在类型上无法提供这个字段**（铸造点注入）——Go 用「**未导出字段 + 包内唯一构造函数**」拿同等效果
2. **让章成为接口的必填方法**——**Go 拿得最顺手的一条**：方法没实现就不满足接口
3. **派生的章写成主章的函数**，不做独立字段——消灭第二份真相
4. **键就是章本身**（同一个对象引用两用）——分叉物理上不可能
5. **拷贝一律整体化**——**Go 在这一条上最脆弱**（手写逐字段拷贝零编译期兜底）
6. **在管子远端断言**（收到没有），别在盖章处断言
7. 两份真相不可避免时，用**影子重建在使用点比对**，并让其中一份明确是「保真元数据，不承重」

**最后一条判据**：
> **盖章的价值不在于消费者少写一个 if，而在于把「我猜你是什么」换成「你自己声明了什么」
> ——所以生产者一旦能不声明，收益就归零。**

## 6. 「能进签名的就别进文档」——必填参数是唯一被证据支持的手段

两个新树**各自独立**发明了同一招，跟语言无关：

- 「Taking the parent as a parameter is what makes that omission **unrepresentable at the call sites**」
- 另一家更极端：一个参数挂着「允许未使用」标注、**运行时根本不用它**，纯粹为了逼调用方
  手上必须有那个作用域

**这正对我们 `runMember` / `runDecisionAgent` 承载的那 8 条协议。** 把归属做成
**必填、无默认、可为 null** 的参数——「忘了」和「想过了，确实没有」从此是两段不同的
程序文本。对端为它付了破坏性变更 + 存量数据作废的代价。

**同一份决策记录顺手替我们否掉了两个方案，理由都是他们实测过的坑**：

- **ctx / ambient 透传**：流式 `yield` 处 ambient 值被回滚，而**写入点在它已失效之后**。
  ⚠️ 我们的 SSE 流式有一模一样的形状——**若考虑这条路必须先实测**（进 §8 待决）。
- **扁平拼串 key**：歧义。落地形态是每段带常量字面量前缀（`a-` / `u-` / `c-`），
  「so a collapsed layout is never ambiguous」。**我们的 `outer/inner` 正是被否掉的那种。**

⚠️ 另一条容易误信的：**元组不是免费的**。有一家的 namespace 是元组，但**落盘时照样 join
再 split**——结构化只保护内存里的比较，**分隔符歧义在持久化边界原样复活**。而
**哈希那一步五家没有一家加分隔符**；唯一真正防住的写法是用一个不可能出现在名字里的字节
（`\0`）当分隔符。

### 7.2 「加维」既不充分也不必要（统一链断掉的证据）

- **不充分**：地址在表里照样被空串穿透；嵌套时 ID 齐全、可见、正确，照样静默送错人；
  **下标裁决补上分支身份之后，`(A,0)` 和 `(B,0)` 之间依然没有序——赢家仍未定义**
- **不必要**：有一家让两个不同的问题**共用同一个 ID** 且完全正确（靠确定性重放 +
  per-task 答案槽）；他们的下标是**整个超步的全局下标**而不是 per-target 下标——
  同一个「下标」两种取法，一个够用一个不够用

⚠️ 「不必要」那条同时反证了我们现行的一处：`Ask` 把「同一批内撞 ID」当 `ErrRunAborted`
当场拒。**「撞 ID ⟹ 静默丢」不是通则，只在「答案槽就是 ID」时成立**——对端答案槽是
per-task 的，撞 ID 出厂即有且正确。这条不是说要改（我们的答案槽确实就是 ID），是说
**那道守卫的合法性依赖「单槽」这个形状，形状变了守卫要跟着重审**。

### 7.3 两条归类订正（照第一版施工会写坏的地方）

- **memo 名单归错了**。它不是寻址问题，是**分类信息没进类型**——正解是 ④（工具自带
  trait 自述）或 §4 问题 6 的「事实交给模型」。第一版预测「裁决前移 ⟹ 名单整个删掉」，
  而 `tool_search` 的揭示集写在 `RunSession`（key 前缀 `__toolsearch_revealed__`，
  `agent_v2/tool_search.go:46`），**跟转交裁决在哪儿算毫无关系**。**照做就是静默不解锁工具。**
- **下标裁决归错了**。它缺的是 ②（提交点全序），不是 ①（加维）——对端在同构位置的做法
  正是把编号从分支本地挪到提交点（写入合并、排序后统一铸号，并发分支不可能拿到相同下标）。
  ⚠️ 这条订正一度只落在本文档：`handoff_tool.go` godoc 与 `todo.md` 登记的修法仍是
  「补一维分支身份」那半（2026-08-20 复查发现，已同步订正）。且 §1.4 复查后**拒绝回到了
  选项空间**——该处「禁止拒绝」不成立，跨批冲突的完整选项是：跨批全序 / 拒绝 / 交还模型。

### 7.4 期望校准（跟原假设相反）

**五家全都带着这类补判断在跑。** 真正把判断从调用点收回去、且合进主干的只有 **3 个**。
按 `TODO|FIXME|HACK` × `flag|allowlist|workaround` 扫五个仓，**没有一条说要消灭它们**——
**这类补判断在他们心里不是债，是常态**，有一家甚至把它写进已批准 ADR 的「负面后果」章节，
缓解措施是「单测覆盖了」。

**修一个造一个也是普遍现象**：最彻底的那次修复（把 wire 给的调用 ID 换成内容指纹），
代价是两张新名单 + 9 个手写调用点 + 2902 行测试。

⟹ **「消灭全部补判断」不是现实目标。现实目标是让「忘了」在源码层面无法表达**
（必填、无默认、进签名不进文档）。
